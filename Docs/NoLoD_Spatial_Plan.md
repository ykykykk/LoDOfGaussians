# 无 LoD 大规模训练实施计划

目标：在单张 RTX 3090 上训练大量实际高斯点，保持原图像素细节；模型总量超过显存时由 SSD 空间块提供后备存储。保留已有全显存快路径，不以分页替代所有场景。

## 实施顺序与验收

1. **独立空间块与原子断点**：参数、Adam 和增点评分按空间排序分块；不可变文件、原子 manifest，保留当前与上一代。验证转换数据、恢复、垃圾回收及流式 PLY。
2. **固定预算 GPU 页缓存**：全局只常驻块包围盒，按视锥载入候选块，再精确裁剪点；脏页写回，天空点冻结。容量不足必须报告，不允许静默丢点。验证换入换出和 Adam 状态。
3. **原像素图像裁块**：修正内参和投影，SSIM 保留 halo，仅对核心区域计算损失；每台相机按确定性顺序覆盖全部裁块，访问状态写入断点。验证与整图渲染对应区域一致。
4. **按块增点**：全局预算按候选数量确定性分配，块内选高分点；新增点合并成页，避免全场张量和大量碎页。验证净增上限、冻结背景、未分裂 Adam。
5. **真实训练集成**：从 DJI 第 47000 步派生独立测试输出，验证训练、保存、续训与导出。按测量瓶颈修订实现。
6. **规模与性能边界**：记录步/秒、每步像素、显存、候选点及磁盘读写；裁块步/秒不能直接和整图比较。合成放大测试仅证明存储/缓存容量，不代表真实一亿点收敛质量。

## 实施结果（2026-09-28）

- 存储、裁块、增点 15 项测试通过。
- CUDA 实际裁块渲染 3 项测试通过，核心像素与整图对应区域最大误差 4.77e-7，SSIM 反传有限。
- DJI 20,050,000 行已转换为 401 个 50,000 行块，其中 100,000 行为冻结背景；原始断点未修改。
- 全部 173 项测试通过，包括实际 CUDA 裁剪、渲染、Adam、磁盘淘汰、断点与采样调度测试。修正了旧测试仍模拟已移除选择接口的过期夹具，原有断言保持不变。
- 新训练入口不加载全场 CPU 参数，不依赖初始化 scaffold；从已有 flat 断点转换开始，尚未新增从零初始化流程。

## 根据实测作出的调整

1. 初版 50,000 行 Morton 块在一个裁块上请求 1205 万缓存行，超过 1200 万预算。分析发现仅 877 个场景点半径大于 10，却将大量普通块包围盒撑大。加入半径分组后，块数 401→410，包围盒中位尺寸由 `6.77×6.01×5.79` 降到 `3.42×1.89×0.98`；参数和 Adam 的 FP32 行哈希与原断点匹配。
2. 初版逐图串行解码约 0.32 秒/步。改为单线程独占缓存预读下一相机、连续四裁块复用；使用独立确定性相机调度，恢复不会因预取提前消耗随机数。
3. 逐块 Python CUDA 调度改为融合页可见性筛选和页内包围盒归约，实测 Adam 加包围盒阶段约 1 毫秒。
4. DJI 宽度 8236 除以 2048 会留下仅 44 像素宽的边条。改为面积近似相等的 5×3 网格，每块约 301 万原生像素，避免用极小裁块制造虚高步/秒。
5. 1200 万行缓存虽然只用约 4.25 GiB 峰值显存，但换页占主导。改为默认最多 8 GiB 缓存、保留 6 GiB 渲染空间，并按模型实际页数限制分配。
6. 新子点按半径分组填充已处理尾页，避免每轮增点留下大量不满页。脏页写回期间定期清理未被两代断点及当前事务引用的旧版本，控制磁盘占用。

## 性能与边界

所有数值来自 RTX 3090、8236×5474 DJI 原图、SH1、约 2005 万总点。吞吐按区间总步数除以总时间计算，不取瞬时最大值。

| 测试 | 区间 | 裁块步/秒 | 说明 |
| --- | --- | ---: | --- |
| 1200 万行缓存 | 47005–47039 | 3.06 | 含换页，排除初始化和最终保存 |
| 自动缓存预算 | 同一 47005–47039 | 8.21 | 同一相机/裁块顺序，约 2.68 倍 |
| 自动缓存预算 | 47005–47079 | 9.54 | 约 28.68 百万核心像素/秒，峰值 6.47 GiB |

80 步完整短测含最终保存共约 23.48 秒；最终保存约 12.92 秒。短测中强制最后一步保存的占比较大，不能当作每千步保存的长期吞吐估计。

这些是分页裁块路径内部的改进，**不是原来整图全显存路径的 2.68 倍**。15 个裁块覆盖一张图，训练采样和 Adam 更新次数也变了。当前约 2000 万点仍保留并优先使用原全显存入口；新入口作为大模型容量方案，未擅自切换正式训练。

## 恢复、增点与规模验证

- 真实模型 47000→47040 后恢复训练，连续三窗口各净增 1000 点，保存至 47043；再次恢复并使用尾页合并，47044 达到 20,054,000 总点。测试阈值刻意降低，只用于验证增点机制，不作为质量推荐参数。
- 47043 PLY 为 19,953,000 场景点，2,075,112,634 字节，头部点数、文件长度和断点一致；完整参数/Adam 有限，块边界有效。
- 固定 150 万缓存行，逻辑总点从 2005 万扩展到 1.0025 亿，缓存峰值仅由 420,010,496 增到 420,050,432 字节（元数据增长）。
- 将实际模型复制五份构造 1.0025 亿点容量压力模型，完成两次真实渲染、反传、Adam 和原子保存，峰值 11.05 GiB。复制模型存在重叠点，只证明该规模的执行和存储链路，不证明真实一亿点场景的收敛质量或长期速度。
- 保存后独立重开一亿点断点，完整扫描全部 69 列参数/Adam、评分及块边界，检查通过；总数 100,250,000，2050 块。
- 单裁块实际可见点/候选页仍受 GPU 容量限制；容量不足明确报错，不能宣称任意分布的一亿点或十亿点都能训练。图像仍需 CPU 解码，SSD 吞吐和空间局部性仍影响性能。

计划各实施阶段及短测已经完成。长期真实大场景质量评估需独立训练预算；本次保留原正式断点和已停止状态，所有新训练均为独立短测输出。
