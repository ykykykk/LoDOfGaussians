# 裁块质量与吞吐优化计划（2026-09-28）

目标：分别验证训练日程是否正确、优化是否保持结果，以及真实吞吐是否改善。所有实验从正式 49100 断点派生独立目录，结束后停止；不覆盖原断点。

1. 分离优化器更新数与整图等效像素覆盖量。学习率、增点和训练终点使用后者，Adam 偏差修正及按步保存使用前者。旧裁块断点按确定性访问记录重建覆盖量，保留原优化器状态。
2. 固定留出相机，用全部原生像素计算 PSNR/SSIM；裁块只用于控制评估显存，每个像素只计一次。对照固定选择、分辨率及指标约定。
3. 增点直接读取最新 GPU 页，仅修改必要页面，检查点统一写盘，保留未变化缓存。对照原先 flush/clear 流程，验证参数、Adam、评分、尾页和持久化一致性。
4. 两个独立解码线程，各自独占分配到的缓存，保持相机序列与恢复顺序；对照单线程测量数据等待。
5. 同断点、同相机顺序进行新旧执行路径 A/B。为覆盖增点，将测试间隔明确设为 10 张等效图，其余分裂阈值和预算保持正常值；此设置只用于短测。
6. 按相同像素覆盖预算进行整图/裁块质量检查，报告采样差异和短测限制，不将裁块步/秒当作整图步/秒。发现质量退化则调整计划，不将未验证配置设为默认。

验收：CPU/CUDA 针对性检查、真实训练/恢复/断点检查通过；明确报告普通步、保存增点、数据等待、显存和固定视角指标。异步保存暂不引入：先避免重复写盘，保持原子快照语义。

## 实施与调整结果

各阶段已完成，188 项测试通过，所有测试训练及评估进程已退出。

- 旧正式断点的 49100 次优化更新重建为约 47140.00137 张整图覆盖量。没有重置 Adam 或改写历史参数；只是为之后的日程使用正确单位。历史过快增点的影响不能通过改计数撤销。
- 新 `pool.densify()` 在常驻页上原位更新，并保留未变化缓存；只有非驻留块仍直接写盘，内存始终按块有界。检查点仍先完成全部脏页写回再原子提交，不做不一致的后台快照。
- `decode_workers=2` 保持相机和裁块顺序，两个独立缓存合计预算仍为 2 GiB。
- 整图对照发现关闭分裂后仍预留增长页面没有收益，改为纯精修时将页数限定到现有模型。整图短测峰值约 17.24→15.23 GiB，耗时 41.86→35.89 秒；增长开启时仍保留预算余量。

## 相同执行序列的速度对照

同一个 49100 源断点、相同 330 个裁块、相同阈值 `5e-5`、两次各净增 600,000 点。短测增点间隔为 10 张等效图，仅为触发验证，不是正式推荐频率。

| 指标 | 单线程 + 清空缓存增点 | 双线程 + 保留缓存增点 |
| --- | ---: | ---: |
| 总墙钟时间 | 145.99 秒 | 101.36 秒 |
| 总吞吐（含增点/保存） | 2.26 裁块步/秒 | 3.26 裁块步/秒 |
| 普通步骤吞吐（含读取/选择，排除保存步） | 6.33 | 12.29 |
| 数据等待合计 | 7.43 秒 | 2.02 秒 |
| 加载/选择合计 | 30.19 秒 | 7.96 秒 |
| 增点/保存合计 | 93.81 秒 | 74.46 秒 |
| 两次增点加保存 | 37.75、38.97 秒 | 26.06、30.15 秒 |

本次总吞吐约提升 44%，是该短测的测量结果；正常 743 张等效图间隔下，增点占比不同，不能保证相同提升比例。保存仍然有停顿。

全部视角均为 8236×5474，以所有原生像素计算 RGB MSE 的全局 PSNR 和 SSIM 图平均值；每个像素计一次，SSIM 保留 halo。没有使用训练视角选择最好结果。

| 模型 | PSNR（dB） | SSIM |
| --- | ---: | ---: |
| 原正式 49100 断点 | 20.86713 | 0.432269 |
| 同序列旧执行方式，两次增点后 | 20.82841 | 0.431884 |
| 同序列新执行方式，两次增点后 | 20.82912 | 0.431873 |

执行方式优化没有观察到明显质量退化，但两组新增点后指标均未提升。短时间增点的结果不能用来宣称画质提高；原像素细节对照仍能看到树冠纹理被平滑或拉长。

随后另从同一源断点派生整图/裁块配对实验：关闭增点，使用相同顺序的 22 张照片。整图每张一步，裁块每张连续覆盖 15 块，总核心像素均为 **991,845,008**，已逐组核对相机名一致。

| 指标 | 整图 22 次更新 | 裁块 330 次更新 |
| --- | ---: | ---: |

此配对短测中裁块质量略好，显存显著减少，等像素处理耗时基本相当。两者 Adam 更新次数不同，这不是严格的数学等价，也不足以证明长期收敛优于整图；保留原全显存路径，不自动替换默认正式训练。

## 真实换页、增点和恢复

- 23,050,000 总点、9,000,000 缓存行运行 24 步，发生 263 次页淘汰，正常保存。
- 从该断点继续，在同样 900 万行缓存下增点至 23,650,000，总峰值约 3.17 GiB；验证了非驻留块与常驻块混合更新。
- 最后恢复遇到一视角需要 9,050,000 行，超过刻意设定的 900 万预算。程序明确报错，没有截断点集。保留输出，从最近完整断点改用 1200 万行重试；依然小于模型，发生 184 次淘汰后成功保存退出。这确认单视角工作集仍是硬边界。
- 不提供 `--steps`，将覆盖终点设为 47165，实际在优化步 49475、覆盖量 47165.00081 自动保存并停止。独立重开断点，全部参数/Adam/评分及 481 个块的边界检查通过。
