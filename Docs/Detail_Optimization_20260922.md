# 细节与图片传输优化验证

环境：Windows、RTX 3090、项目 Python 3.10 / PyTorch 2.14.0+cu126、MSVC 14.44。检查集中在 classic 增点、Resident v2 图片输入及运动鞋训练入口。

## 修改

- classic 子节点由完全重合改为沿父高斯最长局部轴对称分开，偏移补偿该轴尺度缩小造成的方差差；父节点保持原样。
- classic 依据梯度决定是否增点，去掉 `densify_percent` 导致的提前返回。所有 classic 调用在容量有限时优先选择高分叶节点，无候选时跳过 CUDA 重定位，返回实际新增节点数。
- 重定位透明度上界改用当前浮点类型的 epsilon，避免 FP32 中 `1 - 1e-8` 舍入成 1 后产生无穷大 logit。
- Resident v2 同进程图片缓存复用锁页内存，避免同一照片每次上传前重复复制；仍受缓存预算约束。
- 运动鞋预设启用已有的 NDC 梯度评分、像素一致 LoD、自动图片缓存、动态常驻容量和增点诊断。新增脚本 `-Config` 参数。

## 本次结果

120 项回归通过，包含真实 CUDA 分裂、投影、索引 Adam、缓存、SPT 和导出相关检查。5 条警告来自测试调用的上游参考实现。

同一 6000 步粗模型、种子 0、42 张训练图、3002×2005、1000 步细训练；第 200、400、600 步分裂。两组均使用更新后的图片缓存，基线仅恢复提交 `e25b229` 的 `add_new_gs` 方法。

图片上传独立测试：RGB + alpha FP32 张量，每组预热 5 次、统计 20 次同步上传的中位数，包含锁页准备，不含解码、渲染和反向传播。
